# 高级黑白冷蓝滚动叙事作品集设计规范

日期：2026-07-29  
目标分支：`codex/scroll-storytelling-redesign`  
目标网站：`https://www.universitydepartment.store/`

## 1. 目标与成功标准

将现有六项目静态作品集升级为高级滚动叙事型网站，形成“黑色产品发布会舞台 × 高级杂志排版 × 冷蓝AI光感”的统一体验。

成功标准：

- 用户自然向下滚动即可完成浏览，不采用强制滚动吸附或滚轮劫持。
- Hero、关于我、技能、项目、经历和联系六个主要章节都有明确且一致的视觉转场。
- 六个项目从普通卡片网格升级为沉浸式项目展台，但保留真实状态、详情入口和原有文字事实。
- 桌面端具有明显的滚动叙事与景深效果；手机端自动简化为稳定的纵向内容流。
- 支持 `prefers-reduced-motion`，关闭非必要运动后仍能完整阅读和操作。
- 不引入虚假项目成果、源码链接、在线Demo或运行状态。
- 不使用大型前端框架、全屏视频、第三方字体、粒子库或滚动劫持库。
- GitHub Pages、CNAME、旧URL兼容页和六个项目详情页继续正常工作。

## 2. 设计方向

### 2.1 主视觉

采用“高级黑白＋冷蓝微光”：

- 90%使用黑、白、石墨灰和银灰。
- 10%使用冰蓝作为交互、光晕、进度和关键状态强调。
- 关于我章节进行一次黑色到暖白、再回黑色的章节反转。
- 项目区允许每个项目拥有低透明度辅助色，但不改变全站黑白主基调。

## 4. 首页滚动叙事设计

### 4.1 全局框架

- 保留原生页面滚动。
- 增加顶部细线滚动进度条，不遮挡导航。
- 章节通过`data-scene`、`data-reveal`和CSS自定义属性接收状态。
- JavaScript只更新离散状态和CSS变量，不逐帧修改大量DOM样式。
- 使用单一`requestAnimationFrame`调度滚动更新。
- 使用`IntersectionObserver`管理进入、离开和延迟揭示。

### 4.2 Hero场景

Hero占据至少一个完整视口，保持现有身份和核心文案真实性。

主标题调整为三层视觉排版，但语义仍为一个`h1`：

- 把复杂问题
- 转化为可以运行的
- AI产品

交互与动画：

- 页面载入时，眉题、主标题三行、身份和按钮按顺序上移淡入。
- 背景使用纯CSS网格、柔和噪点感和冷蓝径向光晕，不加载图片或视频。
- 现有AI核心图形重构为更简洁的环形线框，随滚动产生轻微旋转与缩放。
- 指针设备上允许不超过12px的缓慢视差；触摸设备关闭指针视差。
- 向下滚动时，标题整体轻微缩小、上移、降低对比度；下一章节从底部覆盖进入。
- 不对正文施加强烈模糊，避免文字阅读困难。

### 4.3 关于我：暖白章节反转

- 整个章节背景由黑色过渡到`--light-section`。
- 文字切换为`--light-text`和`--light-muted`。
- 左侧显示大号`06 PROJECTS`，作为真实项目数量指标，不增加虚假数据。
- 右侧保留现有个人介绍。
- 三项能力卡依次进入，采用短距离上移和边框展开。
- 离开章节后通过下一深色章节自然回归黑色，不做闪烁式颜色切换。

### 4.4 技能：桌面横向轨道

桌面端：

- 技能章节使用sticky容器。
- 用户纵向滚动，卡片轨道在视口内横向移动。
- 五张技能卡依次成为焦点，当前卡片放大约1.03倍，其他卡片降低对比度。
- 每张卡片使用大号编号和英文缩写，不使用彩色图标。
- sticky持续距离控制在合理范围，不能让用户长时间被困在横向轨道。

移动端及减少运动模式：

- 取消sticky和横向映射。
- 使用普通纵向卡片列表。
- 仅保留轻微淡入，不改变阅读顺序。

### 4.5 项目：沉浸式六项目展台

桌面端采用“sticky舞台＋六个原生滚动项目段落”：

- 每个项目拥有一个滚动触发段，舞台在视口中保持sticky。
- 当前项目内容在舞台内切换，浏览器滚动条持续正常前进。
- 不使用整页滚动锁定或滚轮事件阻止默认行为。

舞台组成：

- `01 / 06`项目编号；
- 大字号项目名称；
- 一句真实核心说明；
- 技术标签；
- 当前验证状态；
- “查看详情”真实链接；
- 抽象CSS视觉图形；
- 六段式项目进度指示。

项目切换规则：

- 离场项目缩小至约0.92并降低透明度。
- 新项目从下方或右侧进入，标题使用遮罩揭示。
- 背景低透明光晕切换到项目辅助色。
- 项目编号采用纵向滚动替换。
- 每次切换使用同一套运动语言，不为六个项目设计六套不同动画。
- 焦点、链接和屏幕阅读器中只保留当前项目可交互，隐藏状态不得意外接收键盘焦点。

移动端：

- 不使用sticky舞台。
- 六个项目按纵向大卡片排列。
- 每张卡片保留编号、标题、说明、状态和详情链接。
- 只做进入视口时的淡入和短距离上移。

### 4.6 经历：滚动时间轴

- 桌面端左侧年份与进度线保持sticky，右侧经历内容纵向滚动。
- 当前经历对应年份由灰色变为白色，冷蓝进度线逐步延伸。
- 已浏览经历降低亮度但保持可读。
- 移动端改为普通纵向时间轴，不使用sticky。

### 4.7 联系：电影式收尾

- 回归纯黑背景。
- 主文案为`LET’S BUILD SOMETHING REAL.`，同时保留中文语义辅助文本。
- 邮箱与GitHub保持真实可用。
- 背景使用轻微冷蓝光晕，指针设备可有极弱跟随效果。
- 页脚、年份和返回顶部功能保持完整。

## 5. 项目详情页设计

详情页动画比首页克制，重点仍是信息阅读：

- Hero标题采用一次遮罩揭示和轻微上移。
- 项目编号或类别作为固定视觉锚点，但不遮挡正文。
- 各内容章节进入视口时进行一次淡入和上移。
- 架构层级、流程步骤和技术标签按顺序点亮。
- 上一个／下一个项目导航采用全宽深色转场卡片。
- 项目事实、技术栈、验证状态、隐私声明和风险说明不得修改为未经验证的内容。
- 六个详情页共享同一套动画类和脚本，不复制六套逻辑。

## 6. 运动系统

只使用三种核心运动语言：

1. 上移＋淡入
2. 缩放＋景深
3. 横向擦除／遮罩＋章节反转

建议节奏：

| 动作 | 时长 |
|---|---:|
| 小文字与标签进入 | 450–600ms |
| 标题进入 | 600–750ms |
| 卡片进入 | 550–750ms |
| 区块背景转场 | 900–1200ms |
| 项目舞台切换 | 700–900ms |
| 指针视差响应 | 缓慢插值，不做即时跟手 |

缓动优先使用：

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

禁止：

- 强制整屏吸附；
- 阻止滚轮默认行为；
- 大量霓虹渐变；
- 全站文字发光；
- 巨型鼠标跟随圆球；
- 频繁3D翻转；
- 全屏视频背景；
- 大量粒子；
- 每章节完全不同的转场规则。

## 7. 技术架构

继续使用原生静态技术：

- HTML
- CSS
- JavaScript
- GitHub Pages

建议新增：

- `motion.css`：滚动叙事、状态类、减少运动和移动端降级。
- `motion.js`：统一滚动调度、Intersection Observer、项目舞台、进度和视差。

现有文件职责：

- `style.css`：全站基础视觉、布局、响应式和首页静态状态。
- `project.css`：项目详情页布局与静态视觉。
- `script.js`：导航菜单、返回顶部和年份等基础交互。
- `motion.css`：所有运动状态与滚动场景样式。
- `motion.js`：所有滚动场景运行逻辑。

文件边界要求：

- 不把动画逻辑继续堆进现有`script.js`。
- `motion.js`不得依赖具体项目文案，通过数据属性读取项目索引和辅助色。
- 视觉效果以`transform`和`opacity`为主，避免高频修改布局属性。
- 不引入GSAP、Lenis、Three.js、Swiper或其他外部运行时依赖。
- 不加载外部字体、图片或CDN脚本。

## 8. 状态与数据流

### 8.1 页面初始化

1. 检查`prefers-reduced-motion`。
2. 检查指针和视口能力。
3. 为`html`添加`js`或`reduced-motion`能力类。
4. 初始化Intersection Observer。
5. 初始化滚动进度和需要的sticky场景。
6. 无JavaScript时页面保持完整静态布局。

### 8.2 滚动更新

1. 被动监听scroll事件，只设置“需要更新”标志。
2. 单一`requestAnimationFrame`读取滚动位置。
3. 计算Hero、技能轨道、项目舞台、时间轴的归一化进度。
4. 将进度写入少量CSS自定义属性。
5. CSS负责插值、transform、opacity和颜色表现。

### 8.3 项目舞台

- HTML中的每个项目段落保存真实内容和链接。
- JavaScript根据最接近视口中心的项目段落更新`data-active-project`。
- 当前项目切换时只更新一次离散状态，不在每个滚动像素重建DOM。
- CSS根据状态控制可见性、辅助色和过渡。

## 9. 降级与错误处理

- JavaScript加载失败：展示普通静态章节和六项目纵向网格。
- Intersection Observer不可用：所有内容默认可见，不隐藏正文。
- sticky支持不足：技能和项目自动回退为普通流式布局。
- `prefers-reduced-motion: reduce`：关闭sticky映射、视差、长距离位移、编号滚动和背景大幅变换。
- 页面切回后台时暂停指针视差和非必要动画。
- 视口尺寸变化时重新测量，但使用节流／帧调度，避免连续抖动。
- 任何动画状态都不得阻止链接点击、键盘焦点或浏览器返回。

## 10. 无障碍要求

- 保留跳到主要内容链接、语义标题顺序和现有导航ARIA。
- 动画不能成为获取内容的唯一方式。
- 隐藏项目不得获得键盘焦点或被屏幕阅读器重复朗读。
- 浅色章节文字对比度符合WCAG AA。
- 冷蓝强调色不作为唯一状态标识。
- 所有按钮和链接保留清晰的`:focus-visible`。
- 手机菜单、Escape关闭和焦点恢复行为不得回归。
- 动态数字和项目编号不使用持续的`aria-live`，避免滚动时反复播报。

## 11. 性能预算

- 不新增外部运行时请求。
- 不新增视频背景或大型位图。
- 动画主要使用`transform`和`opacity`。
- 同时使用强模糊的元素数量保持极少。
- 指针视差只在桌面精细指针设备启用。
- 滚动监听必须为passive，并由单一`requestAnimationFrame`统一处理。
- Lighthouse性能目标：桌面不低于90，移动端不低于80；若受GitHub Pages网络波动影响，以本地无节流测试和无明显长任务为辅助依据。
- 360px宽度无水平滚动。
- 主线程滚动过程中不应出现持续的明显卡顿或长任务。

## 12. SEO与内容真实性

- 保留现有页面标题、description、项目真实状态和六个详情页URL。
- 动画不能把主要文本改为Canvas或仅通过JavaScript生成。
- 项目正文必须继续存在于HTML源码中。
- 不添加不存在的GitHub仓库、在线Demo、测试结果、量产状态或商业成果。
- 课堂知识系统保持“前后端本地启动已验证，完整演示仍有限制”的真实状态。
- BTC项目保持已验证的真实测试数量与现有功能边界。

- 1440×900

- 360×800
